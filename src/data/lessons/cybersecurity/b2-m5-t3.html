Основні компоненти Metasploit

Працюючи з Metasploit Framework, ти здебільшого взаємодієш з консоллю msfconsole — головним інтерфейсом фреймворку. Через неї запускають модулі — невеликі компоненти, кожен з яких виконує конкретне завдання: експлуатує вразливість, сканує ціль або проводить перебір паролів.

Перш ніж перейти до модулів, пригадаймо три базові поняття:

Вразливість (vulnerability)
Помилка в дизайні, коді чи логіці системи. Її використання може розкрити конфіденційну інформацію або дати змогу виконати код на цілі.
Експлойт (exploit)
Код, який використовує конкретну вразливість у системі-цілі.
Payload
Код, що виконується на цілі після спрацювання експлойта, щоб досягти потрібного результату — наприклад, отримати доступ до системи чи прочитати дані.

Типи модулів

Модулі згруповані в каталоги за призначенням. Розглянемо основні категорії.

Auxiliary (допоміжні)

Підтримуючі модулі: сканери, краулери та фаззери. Саме ними ми користувалися в лабораторній роботі.

auxiliary/
├── admin
├── analyze
├── crawler
├── dos
├── fuzzers
├── gather
├── scanner
├── sniffer
├── spoof
├── sqli
└── ...

Encoders (енкодери)

Кодують експлойти й payload у надії, що антивірус на основі сигнатур їх не виявить. Такі антивіруси тримають базу відомих загроз і порівнюють з нею підозрілі файли. Енкодери не завжди ефективні, бо антивірус може робити й інші перевірки.

encoders/
├── cmd
├── generic
├── php
├── ruby
├── x64
└── x86

Evasion (обхід захисту)

На відміну від енкодерів, ці модулі напряму намагаються обійти антивірус — з різним ступенем успішності.

evasion/
└── windows
    ├── applocker_evasion_msbuild.rb
    ├── process_herpaderping.rb
    ├── windows_defender_exe.rb
    └── ...

Exploits (експлойти)

Код, що використовує вразливості. Згруповані за системами-цілями.

exploits/
├── android
├── apple_ios
├── linux
├── multi
├── osx
├── unix
└── windows

NOPs

NOP (No Operation) — інструкція, яка нічого не робить. У процесорах Intel x86 їй відповідає байт 0x90: процесор пропускає один цикл. NOP-и використовують як буфер, щоб payload мав сталий розмір.

Payloads

Код, який виконується на цілі. Експлойт лише використовує вразливість, а бажаного результату досягає саме payload: відкриває оболонку, завантажує бекдор, запускає команду. Наприклад, запуск calc.exe на віддаленій системі — безпечний спосіб показати в звіті, що ми можемо виконувати на ній команди.

Найкорисніший результат — інтерактивна командна оболонка (shell), у яку можна вводити команди для виконання на цілі.

Payload поділяються на розділи:

Singles
Самостійні payload (додати користувача, запустити notepad.exe), яким не потрібні додаткові компоненти.
Stagers
Встановлюють канал зв'язку між Metasploit і ціллю. Потрібні для «інсценованих» payload.
Stages
Основна частина payload, яку завантажує стейджер. Так можна доставити більший payload.
Adapters
Обгортки, що перетворюють payload в інший формат — наприклад, в один рядок PowerShell.
За назвою payload видно, він одинарний («вбудований») чи інсценований: у generic/shell_reverse_tcp слова з'єднані підкресленням — це вбудований payload; у windows/x64/shell/reverse_tcp є коса риска між shell і reverse — це інсценований.

Post (постексплуатація)

Модулі для фінального етапу — після того, як доступ до цілі вже отримано: збір даних, подальша експлуатація, закріплення.

post/
├── android
├── linux
├── multi
├── networking
├── osx
└── windows

Робота в msfconsole

Консоль запускають командою:

msfconsole

Після запуску з'являється ASCII-арт і привітання, а промпт стає msf6 (або msf5 — залежно від версії). Тут же видно статистику модулів:

       =[ metasploit v6.0                         ]
+ -- --=[ 2048 exploits - 1105 auxiliary - 344 post       ]
+ -- --=[ 562 payloads - 45 encoders - 10 nops            ]
+ -- --=[ 7 evasion                                       ]

msf6 >

Консоль підтримує більшість команд Linux — наприклад, ls чи ping:

msf6 > ping -c 1 8.8.8.8
[*] exec: ping -c 1 8.8.8.8
64 bytes from 8.8.8.8: icmp_seq=1 ttl=109 time=1.33 ms
А ось перенаправлення виводу (help > help.txt) msfconsole не підтримує — поверне «No such command».

Корисні команди

КомандаЩо робить
help [команда]Довідка про команду (наприклад, help set)
search [запит]Пошук модулів у базі Metasploit
use [модуль / номер]Вибрати модуль і перейти в його контекст
show optionsПоказати параметри вибраного модуля
infoДетальна інформація про модуль
backВийти з контексту модуля до промпта msf6
historyІсторія введених команд
sessionsПерегляд активних сесій
Msfconsole підтримує автодоповнення клавішею Tab — це сильно пришвидшує роботу.

Пошук модулів

Команда search шукає модулі за різними критеріями. Наприклад, за назвою вразливості:

msf6 > search ms17-010

Matching Modules
================
   #  Name                                      Rank     Description
   -  ----                                      ----     -----------
   1  auxiliary/scanner/smb/smb_ms17_010        normal   MS17-010 SMB RCE Detection
   2  exploit/windows/smb/ms17_010_eternalblue  average  MS17-010 EternalBlue SMB Remote...

Далі модуль обирають за номером зі списку:

msf6 > use 2
msf6 exploit(windows/smb/ms17_010_eternalblue) >

Шукати можна й за фільтрами — типом, платформою чи CVE:

msf6 > search type:exploit platform:linux
msf6 > search cve:2017-0143

Ранжування експлойтів

Metasploit оцінює надійність кожного експлойта. Основні рівні — від найгіршого до найкращого:

РівеньНадійність
ManualПотрібна значна ручна взаємодія
LowНизька надійність
AverageПомірно надійний
NormalЗазвичай успішний, можливі незначні проблеми
GreatНадійний і стабільний
ExcellentМайже завжди успішний

Контексти та промпти

За виглядом промпта завжди видно, де ти перебуваєш:

ПромптДе ти
root@kali:~#Звичайний термінал Linux
msf6 >Консоль Metasploit — команди use, search тощо
msf6 exploit(...) >Контекст вибраного модуля (після use)
meterpreter >Сесія Meterpreter після успішної експлуатації
C:\Windows\system32>Оболонка на цільовій системі
Параметри, задані в контексті одного модуля, не переносяться в інший — хіба що ти встановив їх як глобальні.

Параметри модулів

Перед запуском модуля треба задати його параметри. Найважливіші:

ПараметрЗначення
RHOSTSIP-адреса (чи діапазон) цільової системи
RPORTПорт цілі, де працює вразливий додаток
PAYLOADPayload, що використовується з експлойтом
LHOSTIP-адреса атакуючої (твоєї) машини
LPORTПорт твоєї машини для зворотного з'єднання
SESSIONID сесії для постексплуатаційних модулів

Типова послідовність: вибрати модуль, задати параметри, переглянути їх і запустити.

msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(...) > set RHOSTS 192.168.1.100
msf6 exploit(...) > show options
msf6 exploit(...) > exploit

Щоб задати значення глобально (для всіх модулів до виходу з Metasploit), використовують setg:

msf6 exploit(...) > setg RHOSTS 192.168.1.100

Запуск модуля

  • exploit — запускає модуль-експлойт.
  • run — те саме; частіше вживають з неексплойтними модулями (сканерами).
  • exploit -z — запускає й одразу переводить сесію у фоновий режим.

Керування сесіями

Після успішної експлуатації створюється сесія — канал зв'язку між ціллю й Metasploit.

КомандаДія
sessionsПереглянути всі сесії
sessions -i 1Взаємодіяти з сесією №1
background (або Ctrl + Z)Відправити поточну сесію у фоновий режим
