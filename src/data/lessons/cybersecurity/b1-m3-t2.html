Історія Linux

Linux — це сімейство операційних систем з відкритим кодом, яке базується на ядрі Linux. Воно відоме своєю стабільністю, безпекою, гнучкістю та безкоштовністю. Linux широко використовується на серверах, у хмарних технологіях, вбудованих системах, мобільних пристроях (Android працює на ядрі Linux) та пристроях інтернету речей.

Історія Linux почалася у 1991 році, коли фінський студент-програміст Лінус Торвальдс вирішив розробити власне ядро операційної системи для персонального комп'ютера. Він користувався навчальною системою MINIX, але хотів створити щось краще. Перша версія ядра — 0.01 — з'явилася у вересні 1991 року. Проєкт швидко отримав підтримку програмістів з усього світу, які допомагали вдосконалювати код та додавати нові функції, а у 1994 році вийшла перша стабільна версія Linux 1.0.

З часом Linux став однією з найпопулярніших операційних систем у світі. Компанії Red Hat, Canonical (розробник Ubuntu), SUSE та інші сприяли його розвитку, надаючи комерційну підтримку та послуги. Сьогодні на Linux працюють майже всі суперкомп'ютери світу та більшість вебсерверів і хмарних сервісів.

Що таке Linux

Linux — це потужне і гнучке сімейство операційних систем, які можна вільно використовувати і поширювати. Будь-хто може побачити, як працює система, оскільки її вихідний код відкритий для вивчення та модифікації. Ця відкритість заохочує людей з усього світу працювати разом і постійно вдосконалювати Linux.

З моменту появи Linux перетворився на стабільну та безпечну систему, яка використовується всюди: від смартфонів і роутерів до великих суперкомп'ютерів. Він відомий своєю ефективністю — швидко виконує багато завдань навіть на слабкому обладнанні — та економічністю, адже за саму систему не потрібно платити. Навколо Linux склалася велика спільнота, де люди діляться ідеями та допомагають один одному.

Дистрибутив Linux

Дистрибутив Linux — це готова операційна система, яка складається з ядра Linux, системних бібліотек, програм і засобів керування пакетами. Щоб отримати ОС на базі Linux, достатньо завантажити один з дистрибутивів. Існує понад 600 дистрибутивів, ось деякі з найпопулярніших:

  • UbuntuНайпопулярніший для початківців; на ньому наша лабораторна
  • DebianСтабільна основа для серверів і для Ubuntu
  • Kali LinuxДистрибутив для тестування на проникнення та кібербезпеки
  • Fedora / Red Hat / RockyКорпоративна гілка, поширена в компаніях
  • Linux Mint / openSUSEЗручні настільні системи
  • Manjaro / MX Linux / Deepin / SolusІнші популярні дистрибутиви

Архітектура Linux

Операційна система Linux складається з кількох рівнів. Кожен рівень спирається на той, що під ним:

Апаратний рівень
Усі фізичні компоненти: оперативна пам'ять (RAM), диски (HDD/SSD), процесор (CPU) та пристрої введення-виведення. Ядро і бібліотеки забезпечують зв'язок і контроль над ними.
Ядро
Віртуалізує апаратні ресурси: кожен процес «бачить» свої ресурси, ніби працює на комп'ютері сам. Також ядро запобігає конфліктам між процесами.
Системні бібліотеки
Спільні бібліотеки з готовим кодом (наприклад, glibc). Вони — стандартний інтерфейс між програмами та ядром, тож розробникам не треба писати той самий код повторно.
Оболонка (shell)
Інтерфейс користувача: приймає команди, інтерпретує їх і передає запити ядру. Найпоширеніша оболонка — bash.
Системні утиліти
Інструменти для встановлення програм, налаштування мережі, моніторингу, керування користувачами та правами доступу.

Різниця між Linux та Windows

Linux — безкоштовна ОС з відкритим кодом, сумісна зі стандартами UNIX (POSIX). Кожен може переглянути та змінити її вихідний код, що допомагає швидко знаходити й виправляти помилки. Windows розроблена для широкого кола користувачів, яким не потрібні знання програмування: вона проста і зрозуміла у використанні, але є комерційним продуктом з закритим кодом.

Дистрибутиви на кшталт Kali Linux містять сотні інструментів для тестування на проникнення — ними користуються і захисники, і зловмисники.

Ядро Linux

Ядро Linux — серце операційних систем Linux. Це програмне забезпечення з відкритим кодом, яке широко використовується як у промисловості, так і для особистих потреб.

Що таке операційна система та ядро?

Операційна система (ОС) — це програмна система, яка керує комп'ютером, його апаратним і програмним забезпеченням та надає послуги програмам. Вона розподіляє ресурси між обладнанням і програмами, керує пристроями введення-виведення, файловими системами, пам'яттю та надає інтерфейс користувача.

Ядро — це основний компонент операційної системи. Воно забезпечує платформу для програм і служб, які працюють поверх нього. Ядро Linux можна модифікувати відповідно до потреб.

На комп'ютері одночасно виконується багато процесів, тому потрібен посередник, який ефективно і справедливо розподіляє апаратні ресурси між ними. Цим посередником і є ядро. Воно першим завантажується в пам'ять під час старту системи й залишається там до вимкнення.

Розглянемо три найважливіші підсистеми ядра:

  • Планувальник процесів: справедливо розподіляє процесорний час між усіма процесами, запущеними одночасно.
  • Керування пам'яттю: розподіляє оперативну пам'ять між процесами та надає кожному з них окремий віртуальний адресний простір.
  • Віртуальна файлова система (VFS): надає єдиний інтерфейс для доступу до даних на різних файлових системах і фізичних носіях.

Ядро відстежує всі активні процеси. Під час системного виклику exec воно завантажує виконуваний файл у пам'ять. Ядро вирішує, який процес отримає процесор зараз, а який чекатиме, тобто виступає посередником між програмами користувача та апаратним забезпеченням.

Завдання ядра:

  • забезпечувати зв'язок між програмами користувача та апаратним забезпеченням;
  • керувати дисками;
  • керувати пам'яттю;
  • керувати процесами (завданнями).

Типи ядра

1. Монолітне ядро

Усі служби операційної системи працюють у просторі ядра, а його компоненти тісно залежать один від одного. Код такого ядра дуже великий і складний.

Приклади: Unix, Linux, OpenVMS, XTS-400.

Ядро Linux — монолітне, але модульне: драйвери та інші частини можна завантажувати й вивантажувати «на ходу» як модулі (команди lsmod, modprobe), не перезбираючи все ядро. Для безпеки це важливо: шкідливий модуль ядра (rootkit) отримує повний контроль над системою.

Переваги

  • Швидкість: не потрібно постійно перемикатися між режимами користувача та ядра.
  • Тісна інтеграція: служби ефективно взаємодіють між собою, що спрощує оптимізацію.
  • Простіша архітектура: єдина структура, яку легше проєктувати та налагоджувати.
  • Менша затримка: системні виклики та переривання обробляються безпосередньо ядром.

Недоліки

  • Стабільність: помилка в одній службі ядра може «покласти» всю систему.
  • Безпека: вразливість у будь-якій службі ядра компрометує всю систему.
  • Складність обслуговування: зміна однієї частини може вплинути на інші.
  • Обмежена модульність: важче додавати чи видаляти функції без впливу на систему.

2. Мікроядро

Мінімалістичний підхід: у ядрі залишаються лише найнеобхідніші функції (віртуальна пам'ять, планування потоків), а решта служб працює поза ним. Таке ядро стабільніше, бо в просторі ядра менше коду.

Приклади: Mach, L4, AmigaOS, MINIX, K42.

Переваги

  • Надійність: помилка в службі не впливає на всю систему.
  • Гнучкість: служби можна додавати й видаляти, не зачіпаючи систему.
  • Модульність: кожна служба працює незалежно, що спрощує обслуговування.
  • Переносимість: систему легше перенести на іншу апаратну архітектуру.

Недоліки

  • Продуктивність: більше перемикань між простором користувача і простором ядра.
  • Складність: потрібні механізми зв'язку та синхронізації між службами.
  • Складність розробки: більше уваги до проєктування взаємодії служб.
  • Більше ресурсів: обмін повідомленнями між службами потребує пам'яті й процесорного часу.

3. Гібридне ядро

Поєднання монолітного ядра та мікроядра: швидкість монолітного і модульність та стабільність мікроядра.

Приклади: Windows NT (усі сучасні Windows), XNU (macOS), NetWare, BeOS.

Переваги

  • Продуктивність: менше перемикань контексту, ніж у мікроядрі.
  • Надійність: драйвери та компоненти ізольовані краще, ніж у монолітному ядрі.
  • Гнучкість: служби можна додавати й видаляти, не впливаючи на всю систему.
  • Сумісність: підтримує широкий спектр драйверів пристроїв.

Недоліки

  • Складність: поєднує обидва підходи, тож складніше в розробці.
  • Безпека: більша поверхня атаки, ніж у мікроядра, через монолітні компоненти.
  • Обслуговування: складніший дизайн і реалізація.
  • Ресурси: може використовувати більше ресурсів, ніж мікроядро.

4. Екзоядро

Працює за наскрізним (end-to-end) принципом: має якомога менше апаратних абстракцій і просто розподіляє фізичні ресурси між застосунками.

Приклади: Nemesis, ExOS (переважно дослідницькі системи).

Переваги

  • Гнучкість: ОС можна налаштувати й оптимізувати під конкретні застосунки.
  • Продуктивність: програми отримують прямий доступ до апаратних ресурсів.
  • Контроль: точний контроль розподілу пам'яті та процесорного часу.
  • Модульність: служби ОС легко додавати або видаляти.

Недоліки

  • Складність: потребує ретельного проєктування розподілу ресурсів.
  • Складність розробки застосунків: вони мають працювати з обладнанням напряму.
  • Обмежена підтримка: технологія досі переважно дослідницька.
  • Складне налагодження: через прямий доступ до апаратних ресурсів.

5. Наноядро

Надає лише апаратну абстракцію без системних служб. Оскільки сучасні мікроядра теж майже не мають системних служб, ці поняття часто вживають як синоніми.

Приклад: EROS.

Переваги

  • Невеликий розмір: лише найнеобхідніші функції, тож ядро швидке та ефективне.
  • Висока модульність: служби легко додавати або видаляти.
  • Безпека: менша поверхня атаки і менше місць для помилок у коді.
  • Переносимість: працює на широкому спектрі апаратних архітектур.

Недоліки

  • Обмежена функціональність: не підходить для складних застосунків.
  • Складність: усе, чого немає в ядрі, треба реалізовувати окремо.
  • Продуктивність: мінімалізм не завжди дає найкращу швидкодію.
  • Сумісність: підходить не для всіх конфігурацій обладнання та ПЗ.

Термінал

Терміни «термінал», «оболонка» та «інтерфейс командного рядка» часто використовують як синоніми, але між ними є різниця:

Термінал
Середовище введення-виведення — текстове вікно, у якому запущено оболонку.
Оболонка (shell)
Програма-інтерпретатор командного рядка, через яку користувач працює з ОС (наприклад, bash).
Командний рядок (CLI)
Інтерфейс, де команди вводяться текстом, а результати виводяться на екран.

Для роботи з Linux необхідно вміти користуватися терміналом. Будь-яке адміністративне завдання — робота з файлами, встановлення оновлень, керування користувачами — виконується через нього. Хмарні сервери майже завжди керуються саме через термінал (наприклад, по SSH), а на настільних комп'ютерах термінал часто ефективніший за графічний інтерфейс.

Стандарт ієрархії файлової системи

  • Майже всі дистрибутиви Linux дотримуються Стандарту ієрархії файлової системи (Filesystem Hierarchy Standard, FHS). Він визначає набір каталогів, кожен з яких має своє призначення.
  • Пряма похила риска / позначає кореневий каталог — вершину всієї файлової системи.
  • Коли користувач входить до системи, він потрапляє у свій домашній каталог у /home/ (наприклад, /home/sammy). У терміналі домашній каталог позначається знаком ~.
  • Користувач root має окремий домашній каталог /root/. Не плутай: / — «кореневий каталог», а /root — домашня папка користувача root.

Найважливіші каталоги:

/homeДомашні каталоги користувачів

/var/logЖурнали (логи) системи та програм — головне джерело даних для розслідувань

Навігація

Файлова система Linux — це дерево каталогів: всередині каталогів (аналог папок у Windows) можуть бути інші каталоги та файли.

Щоб побачити, у якому каталозі ти зараз працюєш, виконай команду pwd (print working directory — «вивести робочий каталог»):

pwd

Результат буде приблизно таким:

/home/sammy

Це означає, що поточний каталог — sammy, який лежить у home, а той — у кореневому каталозі /. Оскільки sammy лежить у /home, це домашній каталог користувача sammy.

Щоб переглянути файли і каталоги в поточному каталозі, виконай ls (list):

ls

На новій машині команда може нічого не вивести — каталог ще порожній. Корисні варіанти: ls -l — детальний список з правами доступу, ls -a — показати також приховані файли (їхні імена починаються з крапки).

Створити один або кілька каталогів можна командою mkdir (make directory). Наприклад, створимо testdir1 і testdir2:

mkdir testdir1 testdir2

Щоб перейти до каталогу, використовуй cd (change directory):

cd testdir1

Каталоги testdir1 і testdir2 лежать поруч, у різних гілках дерева. Тому, перебуваючи в testdir1, не вийде одразу виконати cd testdir2 — спершу треба піднятися на рівень вище:

cd ..
cd testdir2

Або одразу: cd ../testdir2. А cd ~ (чи просто cd) завжди повертає в домашній каталог.

Робота з файлами

Команда cd працює лише з каталогами. Для файлів є інші команди.

Створити порожній файл можна командою touch:

touch file.txt

Перейменувати файл — командою mv (move). Вона переміщує файл або каталог; «переміщення» в той самий каталог під іншим ім'ям і є перейменуванням:

mv file.txt newfile.txt

Скопіювати файл — командою cp (copy). Зробимо копію newfile.txt з ім'ям file.txt:

cp newfile.txt file.txt

Щоб редагувати файли, потрібен текстовий редактор: vim, emacs, nano тощо. Для початківців найзручніший nano — він простий і не перевантажує незрозумілими командами:

nano file.txt

Відкриється редактор, де можна одразу вводити текст. Щоб зберегти і вийти, натисни Ctrl + X, потім Y і Enter. Підказки з гарячими клавішами nano показує внизу екрана (символ ^ означає Ctrl).

Переглянути вміст файлу можна командою cat — вона виводить файл на екран:

cat file.txt

Якщо файл довгий, зручніше користуватися less — він показує файл посторінково:

less file.txt

Пробіл — наступна сторінка, стрілки — рядок вгору чи вниз, /слово — пошук, q — вихід.

Видалити файл можна командою rm (remove):

rm file.txt
У Linux немає «кошика» для rm: файл видаляється одразу і назавжди. Особливо обережно з rm -r (видалення каталогу з усім вмістом) та sudo.

Мережеві інструменти Linux

Мережеві інструменти допомагають отримувати інформацію про інші системи в мережі, перевіряти зв'язок і діагностувати проблеми. Більшість з них — щоденні інструменти адміністраторів і SOC-аналітиків.

Лабораторна робота 2. Основи Linux

Створення віртуальної машини для Ubuntu

1. Завантаж образ Ubuntu Desktop (версію LTS, з довгою підтримкою) з офіційного сайту Ubuntu.

2. Запусти VirtualBox і натисни New (Створити). Вкажи ім'я машини — Ubuntu, тип ОС — Linux, версію — Ubuntu (64-bit). У VirtualBox 7 одразу вибери завантажений ISO-образ і, як і для Windows, познач Skip Unattended Installation.

3. Задай обсяг оперативної пам'яті. Для сучасної Ubuntu Desktop рекомендовано 4096 МБ (мінімум — 2048 МБ) і 2 процесори.

4. Створи новий віртуальний жорсткий диск: тип VDI, динамічний (файл зростатиме в міру заповнення), розмір — 25 ГБ або більше. Вкажи папку для збереження диска.

У старих версіях VirtualBox ISO-образ вибирається після першого запуску машини у вікні «Виберіть завантажувальний диск» — натисни значок папки і вкажи файл образу.

Встановлення Ubuntu

Встановлення Ubuntu просте й не потребує особливих навичок. Залежно від версії Ubuntu назви екранів можуть трохи відрізнятися, але кроки ті самі.

  1. Запусти віртуальну машину (Start). У меню завантаження обери Try or Install Ubuntu.
  2. Обери мову інтерфейсу — українська, щоб процес встановлення був зрозумілим.
  3. Обери «Встановити Ubuntu» (варіант «Спробувати Ubuntu» запускає систему без встановлення).
  4. Налаштуй розкладку клавіатури, підключення до мережі (у віртуальній машині воно вже є) і натисни «Далі».
  5. Обери тип встановлення: звичайне чи мінімальне. Опцію встановлення стороннього ПЗ (драйвери, мультимедійні кодеки) можна увімкнути — вона додасть підтримку пропрієтарних форматів.
  6. На екрані розмітки диска обери «Стерти диск і встановити Ubuntu». У віртуальній машині це безпечно: стирається лише віртуальний диск, а не диск твого комп'ютера. Окремі розділи для /home чи swap можна створити через «Ручне розмічення».
  7. Обери часовий пояс.
  8. Вкажи своє ім'я, ім'я комп'ютера, ім'я користувача та пароль. Опцію «Вимагати пароль для входу» залишай увімкненою — автоматичний вхід зручніший, але небезпечний.
  9. Натисни «Встановити» і дочекайся завершення — зазвичай це кілька хвилин.
  10. Перезавантаж машину, увійди під своїм користувачем і відкрий термінал (Ctrl + Alt + T).
Готово! Продовжимо практикуватися.

Створення, видалення і зміна користувачів та їхніх ролей

Команда sudo

Команда sudo дозволяє звичайному користувачеві виконати команду з правами суперкористувача (root). Це безпечніше, ніж постійно працювати під root: привілеї надаються тимчасово і лише для конкретної команди, а кожне використання sudo записується в журнал.

Щоб виконати команду з правами root, перед нею пишуть sudo. Система попросить пароль — твого облікового запису, а не root. Так команди з правами root можуть виконувати лише авторизовані користувачі (члени групи sudo).

Приклади:

Оновлення системи:

sudo apt update && sudo apt upgrade

Редагування конфігураційного файлу:

sudo nano /etc/nginx/nginx.conf

Перезапуск служби:

sudo systemctl restart nginx

Керування користувачами

Створення користувача

sudo adduser <ім'я_користувача>

Система попросить пароль нового користувача та додаткові дані — їх можна пропустити, натискаючи Enter.

Надання прав адміністратора

В Ubuntu адміністратори — це члени групи sudo:

sudo usermod -aG sudo <ім'я_користувача>

Видалення користувача

sudo deluser <ім'я_користувача>

Щоб видалити також домашній каталог користувача, додай параметр --remove-home.

Зміна користувача

Змінити ім'я користувача (домашній каталог при цьому не перейменовується — для цього є параметри -d і -m):

sudo usermod -l <нове_ім'я> <старе_ім'я>

Змінити пароль:

sudo passwd <ім'я_користувача>

Групи

Додати користувача до групи (ключ -a обов'язковий — без нього користувача буде видалено з усіх інших груп):

sudo usermod -aG <група> <ім'я_користувача>

Видалити користувача з групи:

sudo deluser <ім'я_користувача> <група>

Інформація про користувачів

Ідентифікатори та групи користувача:

id <ім'я_користувача>

Список усіх користувачів системи:

getent passwd

Налаштування логування та перегляд логів

Зміна налаштувань логування

Класична служба журналювання в Linux — rsyslog. Її налаштування зберігаються у файлі /etc/rsyslog.conf та каталозі /etc/rsyslog.d/. Відкрий файл у редакторі:

sudo nano /etc/rsyslog.conf

Внеси потрібні зміни (наприклад, куди зберігати логи певного типу) і перезапусти службу:

sudo systemctl restart rsyslog

Якщо rsyslog не встановлено (у мінімальних системах), встанови його: sudo apt install rsyslog.

Перегляд системних логів

У сучасних дистрибутивах журнали також веде служба systemd-journald, а переглядаються вони командою journalctl.

Усі логи:

journalctl

Логи певної служби — параметр -u:

journalctl -u <ім'я_служби>

Лише помилки та важливіші події — параметр -p:

journalctl -p err

Стежити за новими записами в реальному часі — параметр -f:

journalctl -f

Приклад: логи входу в систему

Аналог подій 4624/4625 з Windows у Linux — файл /var/log/auth.log (в Ubuntu/Debian). Невдалі спроби входу:

sudo grep "authentication failure" /var/log/auth.log

Історія входів користувачів:

last

Невдалі спроби входу:

sudo lastb
Сотні рядків Failed password з однієї IP-адреси в auth.log — класична ознака підбору пароля до SSH. Саме такі події SOC-аналітики шукають у логах серверів.

Перегляд логів у графічному інтерфейсі

В Ubuntu є графічна програма «Журнали» (GNOME Logs). Якщо її немає, встанови командою:

sudo apt install gnome-logs

Вона показує системні журнали з фільтрами за важливістю та категоріями.

У старих підручниках трапляється програма gnome-system-log (Log File Viewer) — вона застаріла і в сучасних версіях Ubuntu недоступна. Її замінила «Журнали» (gnome-logs).

Для зміни налаштувань та перегляду більшості логів потрібні права адміністратора — використовуй sudo.

Зміна прав доступу до файлів та папок

Перевірка поточних прав

Відкрий термінал і виконай ls -l:

ls -l file.txt
-rw-r--r-- 1 sammy sammy 120 жов 22 10:15 file.txt

Перший стовпець — це права доступу: перший символ — тип (- файл, d каталог), далі три трійки для власника (u), групи (g) та всіх інших (o). У кожній трійці: r — читання, w — запис, x — виконання, - — права немає. Далі — власник (sammy) і група (sammy).

Зміна прав доступу

Права змінює команда chmod. Надати власнику права на читання, запис і виконання:

chmod u+rwx file.txt

Надати право на читання всім:

chmod a+r file.txt

Права також задають числом: r = 4, w = 2, x = 1, і сума — для кожної трійки. Наприклад, chmod 640 file.txt — власник читає й пише (6), група читає (4), інші не мають доступу (0).

Зміна власника та групи

Змінити власника — chown:

sudo chown newowner file.txt

Змінити групу — chgrp (або chown newowner:newgroup одразу):

sudo chgrp newgroup file.txt

Застосування до всієї папки

Щоб змінити права для каталогу і всього його вмісту, додай параметр -R до chmod або chown:

sudo chown -R sammy:sammy /home/sammy/project

Графічний інтерфейс

В Ubuntu права можна змінити і у файловому менеджері «Файли» (Nautilus): права кнопка миші на файлі → Властивості → вкладка Дозволи.

Ніколи не роби chmod 777 «щоб запрацювало»: так будь-який користувач і будь-яка програма зможуть змінити файл. Це одна з типових помилок налаштування, якою користуються зловмисники.
