Створення та запуск віртуальної машини на AWS

У цій лабораторній роботі ти створиш обліковий запис AWS, запустиш віртуальну машину з Windows Server в Amazon EC2 і підключишся до неї через протокол віддаленого робочого столу (RDP).

Інтерфейс консолі AWS регулярно оновлюється, тому вигляд деяких вікон може трохи відрізнятися від скриншотів. Назви кнопок і логіка кроків зазвичай залишаються тими самими.

1. Створення облікового запису AWS

Зареєструйся на сторінці AWS Console — Sign up: вкажи електронну адресу кореневого користувача (root) і назву облікового запису, підтверди адресу та заверши реєстрацію. Під час реєстрації AWS попросить дані банківської картки.

Нові користувачі отримують безкоштовні можливості AWS Free Tier. Умови Free Tier змінювалися (з 2025 року нові облікові записи отримують стартові кредити), тож актуальні умови перевір на aws.amazon.com/free. Одразу після реєстрації увімкни MFA для root-користувача — ти вже знаєш чому з попередніх тем.

2. Запуск віртуальної машини

Після налаштування облікового запису натисни на логотип AWS у верхньому лівому куті або введи console у рядку пошуку. На головній сторінці консолі знайди блок Build a solution і вибери Launch a virtual machine.

Якщо ти новий користувач, активація облікового запису може зайняти до 24 годин.

3. Назва машини

У полі Name вкажи назву своєї віртуальної машини, наприклад TestForGoIT.

4. Вибір AMI

Образ машини Amazon (AMI) — це шаблон із налаштуваннями програмного забезпечення: операційною системою, сервером застосунків і програмами. Можна вибрати Linux або Windows. Ми налаштуємо віртуальну машину з Windows: вибери Windows і образ Microsoft Windows Server 2022 Base з позначкою Free tier eligible.

5. Тип екземпляра

Екземпляр — це віртуальний сервер. Amazon EC2 пропонує багато типів екземплярів під різні задачі: вони відрізняються процесором, пам'яттю, сховищем, мережею тощо. Для лабораторної вибери тип з позначкою Free tier eligible, наприклад t3.micro.

6. Пара ключів

У блоці Key pair (login) натисни Create new key pair.

Задай назву ключа, наприклад keytask, keytest1 або keyforaws. Вибери тип RSA і формат .pem — він знадобиться, щоб отримати пароль адміністратора. Натисни Create key pair.

Переконайся, що файл ключа завантажився: зазвичай це відбувається автоматично після натискання Create key pair.

Пара ключів складається з відкритого ключа, який зберігається в AWS, і приватного ключа — файлу .pem на твоєму комп'ютері. Разом вони дозволяють безпечно підключатися до екземпляра. Повторно завантажити приватний ключ неможливо, тому збережи його в надійному місці й нікому не передавай.

7. Мережеві налаштування та група безпеки

Тут можна налаштувати мережу, підмережу, публічну IP-адресу тощо. Ми залишимо параметри за замовчуванням.

Група безпеки (Security group) — це набір правил брандмауера, які контролюють вхідний і вихідний трафік екземпляра. Можна створити нову групу або вибрати наявну. Залиш Create security group з правилом Allow RDP traffic from.

За замовчуванням RDP дозволено з Anywhere (0.0.0.0/0), тобто з будь-якої IP-адреси в інтернеті. AWS сама попереджає, що це небезпечно: відкритий порт RDP швидко знаходять сканери й починають підбирати паролі. Краще вибери у випадному списку My IP — тоді підключитися зможеш лише ти зі своєї поточної адреси.

8. Сховище

У блоці Configure storage можна додати або змінити сховище. AWS дозволяє додавати томи EBS і томи сховища екземплярів, а також змінювати параметри кореневого тому.

Amazon Elastic Block Store (EBS) надає блокові томи для екземплярів EC2. Вони поводяться як звичайні неформатовані диски, які можна підключити до екземпляра. Поки що залиш усе без змін.

Зверни увагу на напис Root volume (Not encrypted). У робочих середовищах томи EBS варто шифрувати — це вмикається в розділі Advanced або для всього облікового запису в налаштуваннях EC2.

9. Перевірка та запуск

Перевір дані екземпляра в панелі Summary праворуч. Якщо все правильно, натисни Launch instance.

Ти створив(-ла) і запустив(-ла) віртуальну машину на AWS. Тепер перевір її стан і підключись до неї.

10. Підключення до екземпляра

Відкрий список екземплярів: EC2 → Instances. Дочекайся, поки стан зміниться на Running, а перевірки статусу — на 2/2 checks passed. Вибери свій екземпляр і натисни Connect.

Перейди на вкладку RDP client і натисни Get password.

Натисни Upload private key file і вибери файл .pem, завантажений під час створення пари ключів (крок 6). Потім натисни Decrypt password.

AWS розшифровує пароль у браузері, але ніколи не публікуй вміст приватного ключа й не показуй його на скриншотах — з ним будь-хто зможе отримати пароль адміністратора твого екземпляра.

Пароль з'явиться в полі Password. Збережи його, щоб не загубити. Ім'я користувача — Administrator.

Далі натисни Download remote desktop file. Відкрий завантажений файл .rdp, натисни Connect і введи пароль.

Після введення пароля з'явиться попередження про сертифікат віддаленого комп'ютера. Натисни Yes, щоб підтвердити підключення.

Попередження з'являється, бо новий екземпляр Windows використовує самопідписаний сертифікат, якому твій комп'ютер не довіряє. Тут це очікувано: ти щойно створив(-ла) цю машину й підключаєшся до її адреси з консолі AWS. Але якщо таке вікно з'являється під час підключення до знайомого сервера, де раніше його не було, — це привід зупинитися: так може виглядати атака «людина посередині».

Після підключення ти побачиш робочий стіл Windows Server — це означає, що віртуальна машина AWS успішно запущена.

Завершення роботи

Обов'язковий крок. Після завершення вправи видали екземпляр: Instance state → Terminate instance. Перевір, що не залишилося платних ресурсів (томів EBS, публічних IP-адрес, знімків), щоб уникнути неочікуваних рахунків. Також можна видалити пару ключів і групу безпеки, створені для лабораторної.

Щоб не пропустити неочікувані витрати, налаштуй у розділі Billing and Cost Management бюджет з оповіщенням (AWS Budgets) — наприклад, на 1 USD.
