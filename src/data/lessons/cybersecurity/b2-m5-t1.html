Злам SQL-серверів

Тема злому SQL-серверів досить обширна й охоплює різні методи отримання несанкціонованого доступу до баз даних. Пентестер використовує їх, щоб знайти слабкі місця раніше за зловмисників.

Усі техніки з цієї теми застосовуй лише до систем, на тестування яких маєш письмовий дозвіл, або на навчальних полігонах (DVWA, testphp.vulnweb.com, HackTheBox, TryHackMe). Несанкціоноване втручання в чужі системи — кримінальний злочин (стаття 361 КК України).

Що охоплює злам SQL-серверів:

Вивчення структури бази даних
Перш ніж атакувати, важливо дослідити структуру БД — це допомагає знайти вразливості та потенційні точки входу.
SQL-ін'єкція (SQLi)
Найпоширеніша атака: зловмисник вставляє SQL-код у поля введення сайту чи застосунку, щоб виконати шкідливі запити — отримати доступ до конфіденційних даних, видалити чи змінити їх.
Доступ до адміністративних інтерфейсів
Спроби дістатися до інструментів керування (наприклад, SQL Server Management Studio) через перебір паролів, вразливості автентифікації чи перехоплення сеансів.
Слабкі чи стандартні паролі
Адміністратори часто залишають прості або стандартні паролі — це робить сервер вразливим до перебору.
Вразливості ПЗ
Недоліки автентифікації, витоки пам'яті чи вразливості самого SQL-рушія.
Доступ до конфігураційних файлів
Дає змогу змінювати параметри, що керують безпекою сервера та використанням ресурсів.
Експлуатація служб і недоліків ОС
Використання служб на сервері та вразливостей операційної системи, під якою працює SQL-сервер.
Інші канали доступу
Викрадення облікових записів, перехоплення сеансів тощо.

SQL-ін'єкції

SQL-ін'єкція — найпоширеніша й найруйнівніша атака на вебдодатки, керовані даними. Успішна атака коштує організаціям грошей, репутації, даних і працездатності сервісів.

SQL (Structured Query Language) — мова запитів до бази даних. Основні команди для роботи з даними: SELECT (вибрати), INSERT (додати), UPDATE (змінити), DELETE (видалити).

SQL-ін'єкція — це передача SQL-команд через вебдодаток так, щоб їх виконала внутрішня база даних. Зловмисник вводить шкідливі SQL-запити у поля форми, щоб отримати несанкціонований доступ до БД або витягти з неї дані напряму.

Ключова причина SQL-ін'єкцій — не проблема бази даних чи сервера, а те, що вебдодаток не перевіряє належним чином введені користувачем дані перед тим, як підставити їх у SQL-запит.

До чого може призвести SQL-ін'єкція:

  • Отримання конфіденційної інформації: логінів, паролів, персональних і фінансових даних.
  • Зміна, видалення чи додавання даних у базі.
  • Отримання адміністративних привілеїв — доступ до адмінських облікових записів БД чи самого сервера.
  • Виконання додаткових команд: створення облікових записів, запуск зовнішніх програм.
  • Розвиток атаки у внутрішню мережу — доступ до інших систем.

Серверні технології та бази даних

Динамічні вебсайти будують на серверних технологіях: ASP, ASP.NET, Cold Fusion, JSP, PHP, Python, Ruby on Rails тощо. Дані вони зберігають у реляційних базах — Microsoft SQL Server, Oracle, IBM DB2, MySQL. SQL-ін'єкція не експлуатує вразливість конкретного продукту: вона націлена на додатки, що не дотримуються правил безпечного кодування й не перевіряють вхідні дані.

HTTP POST-запит

Коли користувач вводить логін і пароль та натискає «Відправити», браузер надсилає ці дані серверу. На відміну від GET, метод POST передає дані в тілі запиту, а не в URL. Приклад запиту до сторінки входу:

POST /login HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:97.0) Firefox/97.0
Content-Type: application/x-www-form-urlencoded
Content-Length: 29
Connection: close

username=admin&password=Password123
  • POST /login HTTP/1.1 — запит на адресу /login методом POST.
  • Host — адреса хоста, якому надсилається запит.
  • Content-Type: application/x-www-form-urlencoded — тип даних форми.
  • username=admin&password=Password123 — дані форми: логін admin і пароль Password123.

Звичайний SQL-запит

Сервер підставляє введені користувачем значення в заготовку запиту й виконує його. Для перевірки логіна й пароля запит зазвичай має такий вигляд:

SELECT * FROM users WHERE username = 'admin' AND password = 'Password123'
  • SELECT * — вибрати всі стовпці;
  • FROM users — з таблиці users;
  • WHERE username = 'admin' AND password = 'Password123' — лише ті рядки, де логін і пароль збігаються.

Запит з ін'єкцією

Якщо додаток не перевіряє введені дані, зловмисник може ввести в поле логіна Blah' OR 1=1 --. Тоді запит перетвориться на:

SELECT Count(*) FROM Users WHERE UserName='Blah' OR 1=1 --' AND Password='Springfield'

Умова OR 1=1 завжди істинна, а -- починає коментар і «відрізає» решту запиту разом з перевіркою пароля. Синтаксичної помилки немає, запит виконується — і додаток вважає зловмисника автентифікованим. Ось чому такий код небезпечний:

strQry = "SELECT Count(*) FROM Users WHERE UserName='" + txtUser.Text +
         "' AND Password='" + txtPassword.Text + "'"
Головний захист — параметризовані запити (prepared statements): введені дані передаються окремо від тексту запиту, і база даних ніколи не сприймає їх як код. Додатково допомагають перевірка вхідних даних, принцип найменших привілеїв для облікового запису БД і приховування докладних повідомлень про помилки.

Внутрішньосмугова ін'єкція

Атаку й отримання результату виконують одним каналом. Її використовують, щоб зібрати інформацію про структуру БД, витягти конфіденційні дані, змінити чи видалити їх, виконати додаткові команди.

Припустимо, параметр у URL обирає дані з бази:

http://example.com/products?id=1

Пентестер підставляє в нього ін'єкцію:

http://example.com/products?id=1' OR '1'='1

Умова '1'='1' завжди істинна, тож запит поверне всі записи таблиці products.

Ін'єкція на основі помилок

Зловмисник навмисне змушує БД повернути повідомлення про помилку, а потім аналізує його, щоб зібрати дані про структуру. Застосовують, коли інші методи недоступні. Для запиту:

SELECT * FROM products WHERE id_product=$id_product

шкідливий запит для Oracle може мати вигляд:

http://www.example.com/product.php?id=10||UTL_INADDR.GET_HOST_NAME((SELECT user FROM DUAL))

Функція UTL_INADDR.GET_HOST_NAME спробує знайти хост з іменем, що дорівнює імені користувача БД, не зможе й поверне помилку на кшталт ORA-292257: host SCOTT unknown — а в ній буде ім'я користувача.

UNION-ін'єкція

Зловмисник приєднує свій запит до оригінального через UNION, щоб вивести значення з інших таблиць. Для UNION потрібна однакова кількість стовпців в обох запитах, тому спершу її визначають за допомогою ORDER BY:

ORDER BY 10--

Якщо помилки немає, стовпців щонайменше 10; якщо з'являється «Unknown column '10'», їх менше. Методом проб визначають точну кількість. Далі перевіряють типи стовпців:

UNION SELECT 1,null,null--

і виконують основну UNION-ін'єкцію.

Сліпа (інференційна) ін'єкція

Її застосовують, коли додаток вразливий, але результат ін'єкції не видно: замість корисної помилки показують звичайну сторінку. Тоді базі ставлять запитання, на яке є відповідь «так/ні», і роблять висновки за поведінкою сторінки — зокрема за штучною затримкою:

http://example.com/login?username=admin' AND IF(SUBSTRING(password,1,1)='a',SLEEP(5),0)--

Функція SUBSTRING() бере перший символ пароля, а SLEEP() затримує відповідь на 5 секунд, якщо цей символ дорівнює a. Якщо сторінка відповіла із затримкою — перший символ вгадано. Так посимвольно відновлюють пароль. Метод повільний, бо на кожен біт даних потрібен окремий запит.

Позасмугова ін'єкція

Найскладніша: результат отримують окремим каналом — через DNS- чи HTTP-запит до сервера зловмисника. Її використовують, коли той самий канал для атаки й результату недоступний. Наприклад, у MS SQL Server для DNS-запитів застосовують xp_dirtree, в Oracle для HTTP-запитів — пакет UTL_HTTP. Перевага для зловмисника в тому, що дані «виносяться» через DNS, навіть якщо прямий вихід у мережу заблоковано.

Злам вебсерверів

Вебсервери — критично важливий компонент інфраструктури: одна вразливість у конфігурації може призвести до компрометації сайту. Злам вебсервера — виявлення та експлуатація його вразливостей для несанкціонованого доступу чи інших шкідливих дій.

Чому аналіз безпеки вебсерверів важливий:

  1. Вебсервери дають доступ до сторінок, застосунків і ресурсів через інтернет, тож часто стають головною мішенню.
  2. Вони можуть містити різні вразливості: некоректні налаштування, діри в ПЗ, SQL-ін'єкції, DoS, вади автентифікації.
  3. На них зберігається конфіденційна інформація — персональні дані, банківські реквізити, корпоративні секрети.
  4. Вони доступні з інтернету, тож постраждати може велика кількість користувачів.
  5. Через постійну появу нових загроз регулярне тестування безпеки стає критично важливим.

Як працює вебсервер

Вебсервер зберігає, обробляє й доставляє вебсторінки клієнтам за протоколом HTTP. Клієнт (браузер) генерує HTTP-запит; сервер збирає потрібний вміст зі сховища чи серверів застосунків і відповідає HTTP-відповіддю. Якщо знайти ресурс не вдається — повертає повідомлення про помилку. Це класична модель клієнт-сервер, де браузер — клієнт, а вебсервер — сервер. Найпоширеніші програми вебсерверів: Apache, Microsoft IIS, Nginx, Tomcat.

Види атак на вебсервери

Зловмисник може компрометувати вебсервер багатьма способами: DoS/DDoS, перехоплення DNS, обхід каталогів, MITM, фішинг, пошкодження сайту, неправильна конфігурація, розщеплення HTTP-відповідей, отруєння веб-кешу, перебір SSH і злам паролів.

Перехоплення DNS-сервера

DNS перетворює доменне ім'я на IP-адресу. При перехопленні зловмисник компрометує DNS-сервер і змінює його записи так, щоб запити користувача йшли на підроблений сервер. Тоді, ввівши легальну адресу, користувач потрапляє на фальшивий сайт.

Рекурсивний DNS-запит: клієнт просить локальний DNS-сервер знайти IP-адресу, а той, якщо не знає відповіді, сам послідовно опитує кореневі DNS-сервери, сервери зони com і, нарешті, сервер зони example.com, після чого повертає відповідь клієнту. Розуміння цього процесу важливе для атак на DNS.

Обхід каталогів (Directory / Path Traversal)

Якщо вебсервер приймає дані від браузера без належної перевірки, зловмисник може маніпулювати URL, щоб вийти за межі кореневого каталогу. Для цього використовують послідовність ../ (крапка-крапка-коса риска), піднімаючись по дереву каталогів до конфіденційних файлів. Атаку зазвичай проводять прямо з браузера, методом проб і помилок.

Розщеплення HTTP-відповіді (HTTP Response Splitting)

Зловмисник додає у поле введення символи переходу на новий рядок (\r\n) разом з власними даними заголовків, через що сервер розбиває одну відповідь на дві. Атака експлуатує вади перевірки введення. Контролюючи першу відповідь, зловмисник може, наприклад, перенаправити користувача на шкідливий сайт. На цьому ж механізмі ґрунтуються XSS, CSRF та отруєння кешу.

Injection-Header: MaliciousData\r\nContent-Length: 0\r\n\r\n

Отруєння веб-кешу (Web Cache Poisoning)

Зловмисник підміняє кешований вміст (на проксі чи CDN) шкідливим. Він змушує кеш очистити справжній вміст і зберегти спеціально сформований запит. Після цього всі користувачі цього кешу отримують шкідливий вміст, доки кеш не очиститься. Атака можлива, якщо сервер і додаток мають вади розщеплення HTTP-відповідей.

Перебір SSH (SSH Brute Force)

SSH створює зашифрований тунель між хостами (зазвичай порт TCP 22). Зловмисник сканує сервер на відкритий порт 22, а потім перебором підбирає облікові дані. Отримавши доступ, він може тим самим тунелем непомітно передавати шкідливе ПЗ. Для перебору використовують Hydra, Medusa, Ncrack.

Злам паролів вебсерверів

Зловмисник експлуатує слабкі механізми автентифікації. Найпоширеніші паролі — password, root, admin, administrator, demo, test, guest, qwerty, імена домашніх тварин тощо. Цілі — SMTP- і FTP-сервери, вебресурси, SSH-тунелі, вебформи. Паролі добувають соціальною інженерією, фішингом, перехопленням трафіку, кейлогерами або автоматизованими інструментами: THC Hydra, Ncrack, RainbowCrack.

DoS / DDoS-атаки

При DoS/DDoS-атаці сервер засипають величезною кількістю фальшивих запитів, щоб він перестав відповідати легальним користувачам. Мішенню часто стають важливі сервери — банківські, платіжні шлюзи, кореневі сервери імен.

DoS/DDoS можуть завдати серйозної шкоди, тож їх проводять лише з письмового дозволу власника системи й з дотриманням етичних і правових норм. У навчальних лабораторіях атаку спрямовують тільки на власні тестові сервери.

Інструменти аналізу вебсерверів

Nmap

Nmap (Network Mapper) — потужний інструмент сканування мережі. Основні можливості:

  • Сканування портів — виявлення активних портів і служб на них;
  • Визначення версій служб — щоб знайти вразливі версії ПЗ;
  • Оцінка безпеки через вбудовані скрипти (NSE);
  • Визначення ОС за відповідями на пакети;
  • Швидке сканування великих мереж;
  • Звіти з результатами сканування.

Приклад. Просканувати мережу 192.168.1.0/24 й знайти активні хости та відкриті порти:

nmap 192.168.1.0/24
Nmap scan report for 192.168.1.1
PORT    STATE SERVICE
22/tcp  open  ssh
53/tcp  open  domain

Nmap scan report for 192.168.1.2
PORT    STATE SERVICE
80/tcp  open  http
443/tcp open  https

Nmap scan report for 192.168.1.3
PORT    STATE SERVICE
21/tcp  open  ftp
22/tcp  open  ssh
80/tcp  open  http

Так ми знайшли три активні хости й для кожного визначили відкриті порти та служби.

Metasploit Framework

Metasploit Framework — потужний набір інструментів для тестування на проникнення (докладніше розглянемо в лабораторній роботі). Його ключові можливості:

  • База вразливостей: відомості про відомі вразливості ПЗ, ОС, протоколів і служб;
  • Експлойти та модулі: готові засоби для атак на системи й вебдодатки;
  • Гнучке налаштування під конкретну задачу тестування;
  • Модульна структура з можливістю розширення сторонніми модулями;
  • Керування й звітність: моніторинг прогресу та детальні звіти.

Підсумки

  • SQL-ін'єкція можлива тоді, коли додаток не перевіряє введені дані й підставляє їх прямо в запит. Типи: внутрішньосмугова (Error-based, UNION-based), сліпа та позасмугова.
  • Головний захист від SQLi — параметризовані запити, перевірка введення й найменші привілеї для облікового запису БД.
  • Вебсервери атакують через перехоплення DNS, обхід каталогів, розщеплення HTTP-відповідей, отруєння кешу, перебір SSH, злам паролів і DoS/DDoS.
  • Для аналізу й експлуатації пентестери використовують SQLMap, Burp Suite, OWASP ZAP, Nmap і Metasploit — і лише в межах дозволеного тестування.
